# Product knowledge

Owner: `product-designer`

This area describes current product behavior from the user's point of view.
Keep product intent, user workflows, interaction behavior, UX principles, and
user-facing acceptance signals here when they describe implemented behavior.

## Documents

- [Product overview](product-overview.md): current product purpose,
  positioning, audiences, workflows, strategic boundaries, and acceptance
  signals.

Use this area for:

- product goals that are true of the current system
- strategic positioning grounded in implemented behavior
- primary users and jobs to be done
- user workflows and interaction states
- UX principles that should guide future changes
- user-facing acceptance signals
- product-readiness notes when they reflect the current release state

Do not use this area for speculative future features or active execution
notes. Put planned work in `_docs/plans/`.
