# Decisions knowledge

Primary owner: `technical-architect`

The technical architect owns the decisions index and architecture decision
records by default. Other specialist roles contribute decisions from their
discipline. The documentation specialist owns cross-links and placement.

## Documents

- [Guidance ownership model](guidance-ownership-model.md): guidance is a
  first-class asset with role-owned guidance, workflow-owned activity guidance,
  project-owned overrides, and deferred default routing.
- [Product ownership and Boss authority](product-ownership-and-boss-authority.md):
  the default workflow's product/release boundaries and human decision model.
- [Forced update recovery](forced-update-recovery.md): backup-first force update,
  ownership boundaries, audit, and retention semantics.

Add new records here when a decision needs to explain an accepted current
tradeoff across product, requirements, architecture, security, quality, or
operations.

Use this area for:

- accepted architecture decisions
- product, requirements, security, quality, and operations tradeoffs
- decisions that explain why a current behavior exists
- decision records that future plans should preserve
- links from decisions to the docs they affect

Decision records should separate current accepted decisions from open
questions. Keep rejected or historical options only when they explain an
important current tradeoff.
